# 正反对照

前三组摘自仓库 README 的早期写法；后续匿名化示例用于说明复核方法，不代表任何项目未经核实的实际功能。看似正常的句子也可能因重复、无谓扩写或语义偷换而不合格。

## 1. 排比总结与翻译腔

**病灶**：为了显得完整，用「能 A、能 B、能 C」把功能串成一口气读完的排比句。读者拿不到任何具体信息。

> 早期原型：能接入、能切换、能对轴、能在已经回放的舞台上定位。采集、混音、跨源自动同步没有做。

> 早期原型。已经能同时播放多个音视频源、切换画面和声音，并跳到回放中的指定时间。采集、混音和跨源自动同步还没做。

**为什么**：「对轴」「在舞台上定位」是内部术语换了个说法，外部读者猜不到是什么功能。拆成具体的动作用语，字数差不多，信息量完全不同。

## 2. 单字伪口语

**病灶**：把 `settle` / `guard` / `fall back` 按字面硬翻成「落定」「守着」「退化为」，再扩散成「落位」「交回」「换出」「留着」。看着像口语，其实没人这么说话。

> 切布局只改落位，不重开播放器、不动声音与同步。放不下的源不会退回整个舞台。

> 切换布局只调整各画面的位置，不会重新打开播放器，也不影响声音和同步。空间不够时格子保持空白。

**为什么**：「落位」在正常开发用语里不存在。判断方法很简单：跟同事口头聊这个功能时，你会说「调一下位置」，不会说「改落位」。

## 3. 直译状态词

**病灶**：把内部提示文案原样搬进文档，读者要自己翻译一遍才知道意味着什么。

> **「位置已落定」不等于「目标帧已呈现」**：Seek 提交只证明播放器报告了请求的位置，账户文案保持 `position settled, the frame is not confirmed`。

> **Seek 只保证位置被接受，不保证画面已经切过去**：播放器会回报收到了请求，但不确认那个时间点的帧已经显示出来。

**为什么**：`settled` 在这里的准确含义是「请求被接受」，不是「已经到位」。照字面翻成「落定」正好把意思弄反。

## 4. 模糊指代与聊天式过程

**病灶**：把开发群里的「这块」「跑通」「兜住」「做相关处理」直接搬进正式说明。它没有告诉读者谁执行操作、失败时会怎样。

> 这边会兜住失败，再跑一遍就行。

> （写法示例）任务提交失败时，调用方保留原请求，并允许使用相同参数重试。

**为什么**：改写示例有明确的对象和结果，但**不能在未核验代码时把它当成真实功能**。若只能确认「失败时返回错误」，就只写这个事实，不能补出「保留原请求」或「允许重试」。

## 5. 删空话，不删用户需要的限制

**病灶**：只为了减字数，把具体的错误处理行为一起删掉。

> 自动恢复失败时不会覆盖现有配置，并提示失败原因。

> 自动恢复失败时保留原配置，并提示失败原因。

**为什么**：删掉重复修饰，但仍保留「原配置不会被覆盖」这一信息。若无证据证明保留原配置，不能采用这两种说法。

## 6. 拆段后出现完整句重复

**病灶**：原来一个长段落被拆开，编辑时把同一条说明复制了两遍。单句语法完全正常，整段却明显不合格。

> 列表包含名称、状态、创建时间和到期时间。已撤销的记录仍然保留，直到用户删除。列表包含名称、状态、创建时间和到期时间。

> 列表包含名称、状态、创建时间和到期时间。已撤销的记录仍然保留，直到用户删除。

**为什么**：只改第一遍 lint 提示的长句，不能保证拆分后的文档没有重复。终稿必须从头复读；`duplicate-sentences` 可以提示完全相同的较长句子，但不同措辞的同义重复仍要人工辨认。

## 7. 无谓扩写与语义偷换

**病灶**：为了显得正式，把简洁准确的事实变成冗长句，或把尚不确定的行为写成保证。

> 服务可能在请求超时后继续执行，因此用户可以先进行一次状态查询操作，再决定是否重新进行提交。

> 请求超时后，服务可能仍在执行。重新提交前先查询状态。

> 请求超时后，服务会完成操作。重新提交前查询状态。

**为什么**：第二句保留了「可能」和先查询的要求；第三句把不确定行为改成确定承诺，是错误改写。避免冗余不能以删除限定词、改变失败语义为代价。这些均为说明写法的虚构示例，实际行为要按代码核实。

## 英文侧

同样的毛病，英文版换成了营销词和被动语态：

| 不要 | 要 |
| --- | --- |
| seamlessly integrates with your existing workflow | works with the files and URLs listed below |
| robust error handling out of the box | reports the failing source and keeps the session running |
| empowers developers to effortlessly … | lets you … |
| is designed to be highly configurable | supports A, B, and C; other cases are not configurable |
