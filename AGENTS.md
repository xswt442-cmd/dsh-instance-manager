# Agent guide

`dsh-instance-manager` is a DSH host + web plugin for managing local and paired DSH Web instances.

## Engineering

- Keep `package.json#version` and `lib/shared.js#VERSION` equal. Keep `README.md` / `README.en.md` and `docs/CHANGELOG.md` / `docs/CHANGELOG.en.md` in step; `npm run docs:check` compares the pairs declared in `docs.config.mjs`.
- The four marked blocks in `lib/shared.js` and `lib/client.js` are generated by `dsh-mini-utility-dock`: edit the fragment, run the matching `*.sync` script, never edit a block. `npm test` runs the `*:check` gates; raise the pin and re-sync all blocks in one commit.
- A `check` only compares blocks its pinned version knows, so a green result is not proof that a newer block matches; the marker-order tests are.
- `requestNeedsBearer` decides which credential a route demands; the guard decides whether a request proceeds. Keep both, and keep local and fleet trust boundaries separate. An unexpected route failure answers a fixed `code` only and logs the exception.
- The Configuration chapter of both READMEs must be operable on its own: the `live` / `startup` sections, every field's range and default, the environment variables, and what `DSHIM_FLEET_TOKEN_REF` references.
- Read optional DSH services only inside `ctx.inject(...)` callbacks.
- The DSH floor must agree in the README badge, `engines.dsh`, and the optional `@deepseek-ai/dsh` peer. Keep the range unbounded.
- `scripts/deploy-profile.ps1` and `scripts/auth-topics.ps1` are local conveniences: keep them out of installation instructions and free of owner, account, or absolute path defaults.

## Changelog

- One bullet per shipped change, at most two short sentences, in the README's register: no implementation narrative, no root-cause essay, no conversational verbs or emphasis quotes.
- `Unreleased` is for changes a user would notice; deferred work belongs in a handoff note.
- Do not name another repository; `dsh-mini-utility-dock` is the only exception and only when it is the subject.

## Releases

Maintainers commit straight to `dev` and fast-forward `main`; CI still runs when an outside pull request arrives. `docs/RELEASING.md` is the runbook; `scripts/release-notes.mjs` cuts release notes from `docs/CHANGELOG.md`.

## Verify

```sh
npm test
npm run docs:check
for f in lib/*.js; do node --check "$f"; done
npm pack --dry-run
```

## Scope

- Change only what the task requires. Keep tracked files self-contained: no personal paths, credentials, or one-off logs. Git operations beyond the current task need explicit authorization.
